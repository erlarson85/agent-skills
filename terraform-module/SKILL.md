## Module Structure

Every module lives at `modules/<name>/` in the `dco-terraform` repo. Names are lowercase with hyphens (e.g., `azure-windows-vm`, `ec2-instance`).

```
modules/my-module/
├── package.yaml          # Required: provider + version
├── main.tf               # Implementation (starts with /* */ block comment)
├── variables.tf          # Inputs (every var needs description + validation)
├── outputs.tf            # Outputs (every output needs description)
├── versions.tf           # required_version + required_providers
├── examples/basic/main.tf  # Usage example (optional but encouraged)
├── tests/main.tftest.hcl   # Native tofu tests (optional but encouraged)
├── .terraform-docs.yml     # README template (optional)
└── README.md               # Auto-generated by terraform-docs — never edit
```

## package.yaml

```yaml
provider: azurerm
version: "1.2.0"
```

- `provider`: one of `aws`, `azurerm`, `vault`, `cloudflare`, `null` (use `null` for data-only modules like `product-tags`, `engineering-roster`, `asu-ips`)
- `version`: `"major.minor.fix"` — always quoted, always bump on changes
- Validated by Yamale against `modules/schema.yaml`
- **Gotcha:** If you forget to bump, Jenkins silently skips publish (version already exists in registry)

### When to Bump

| Change | Bump | Example |
|--------|------|---------|
| Bug fix, docs, internal refactor (no interface change) | patch | `1.2.0` → `1.2.1` |
| New variable with a default, new output, new optional feature (additive, non-breaking) | minor | `1.2.0` → `1.3.0` |
| Could break existing consumers (removed/renamed var or output, new required var, type change, destroy+recreate) | major | `1.2.0` → `2.0.0` |

## main.tf Header

Start `main.tf` with a block comment — terraform-docs renders this as the README header:

```hcl
/*
 * My Module Name
 *
 * Brief description of what it creates and why.
 *
 * Module usage:
 * ```
 * module "example" {
 *   source  = "jfrog-cloud.devops.asu.edu/asu-terraform-modules__dco-terraform/my-module/aws"
 *   version = "~> 1.0"
 *
 *   product_key = "ddt"
 *   environment = "prod"
 * }
 * ```
 */
```

## Source Format

Consuming repos reference modules as:

```hcl
module "thing" {
  source  = "jfrog-cloud.devops.asu.edu/asu-terraform-modules__dco-terraform/<module-name>/<provider>"
  version = "~> 1.0"
}
```

During PR builds, `asu-terraform-modules` is swapped to `asu-terraform-modules-testing` automatically.

## Variable Conventions

- Every variable needs a `description`
- Use `validation {}` blocks for enums, patterns, and conditional requirements
- Use `object()` with `optional()` fields and defaults for complex inputs
- Use `check {}` blocks (preconditions) for cross-variable dependencies
- Mark secrets with `sensitive = true`
- Tags: accept `var.tags` as `map(string)` — never depend on `product-tags` internally (the consuming repo handles that)

## Provider Versions

Declare in a separate `versions.tf`:

```hcl
terraform {
  required_version = ">= 1.8"

  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = ">= 5.0.0"
    }
  }
}
```

Use `>=` or `~>` — never pin exact versions.

## Testing

Tests live in `tests/main.tftest.hcl` using `mock_provider` blocks (no real infra):

```hcl
mock_provider "aws" {}

run "test" {
  variables {
    product_key = "tmi"
    environment = "test"
  }
}
```

Use `override_module` or `override_resource` when downstream resources need computed attributes:

```hcl
override_module {
  target = module.vm
  outputs = {
    resource_id = "/subscriptions/000/resourceGroups/rg/providers/Microsoft.Compute/virtualMachines/test"
  }
}
```

Run with: `tofu test`

## File Organization

- Split resources by concern: `iam.tf`, `s3.tf`, `ec2.tf` — not everything in `main.tf`
- Submodule references go in `module-*.tf` files (e.g., `module-product-tags.tf`)
- Examples are single-file — include `terraform { required_version = ">= 1.8" }` at the top

## terraform-docs

Add `.terraform-docs.yml` to customize README output:

```yaml
formatter: markdown table

content: |-
  {{ .Header }}

  ## Example

  ```hcl
  {{ include "examples/basic/main.tf" }}
  ```
  {{ .Requirements }}

  {{ .Providers }}

  {{ .Modules }}

  {{ .Resources }}

  {{ .Inputs }}

  {{ .Outputs }}
```

## Publishing

- **PR branches** → published to `asu-terraform-modules-testing` (test in consuming repos)
- **main** → published to `asu-terraform-modules` (production)
- Jenkins skips publish if the version already exists in the registry
- Successful publishes post to `#devops-infrastructure` Slack

## Commit Convention

```
feat(azure-windows-vm): add data disk support
fix(product-tags): correct component tag merge order
chore(ec2-instance): bump version to 2.1.0
```

## Checklist for New Modules

1. Create `modules/<name>/` with all required files
2. Set `package.yaml` with correct provider and initial version `"0.1.0"`
3. Write the `main.tf` header comment
4. Add at least one example in `examples/basic/main.tf`
5. Add a test in `tests/main.tftest.hcl`
6. Run `tofu fmt`, `tofu validate`, `tflint`, and `tofu test`
7. Commit: `feat(<name>): initial module`
